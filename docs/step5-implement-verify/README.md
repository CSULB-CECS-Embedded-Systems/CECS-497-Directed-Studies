# Step 5 - Implement and Verify

Implement through small feature branches and pull requests. Keep source files in `software/`, hardware artifacts in `hardware/`, procedures in `tests/`, and evidence in `results/`.

## Recommended progression

1. Establish a working baseline.
2. Verify each interface or subsystem independently.
3. Integrate one capability at a time.
4. Run the planned verification procedures.
5. Link results to requirement IDs.
6. Record failures and corrective decisions rather than deleting unsuccessful evidence.

## Review gate

- The repository can be built or reproduced from its instructions.
- Important changes are traceable through issues, commits, and pull requests.
- Verification evidence is retained and labeled.
- Requirement status is supported by evidence.
- Known defects and incomplete work are disclosed.
